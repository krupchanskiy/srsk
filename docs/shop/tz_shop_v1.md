# Магазин — ТЗ v1

Раздел уровня «Кухня» и «CRM». Задача: принимать товар, быстро продавать, понимать,
кому и сколько должны, и видеть прибыль — не заводя вторую бухгалтерию.

## Граница ответственности

Магазин знает про **товар и его движение**. Финмодуль знает про **деньги**.
Пересечение ровно в трёх точках: выручка, сдача денег казначею, расчёт с владельцем товара.
Всё это делается существующими механизмами финмодуля, новых сущностей для денег не вводим.

## Два источника товара

| | Реализация (консигнация) | Свой выпуск |
|---|---|---|
| Пример | книги, одежда, аюрведа | мурти Госвами (делает Мастерская) |
| Чей товар | владельца, лежит у нас | наш |
| Когда возникает долг | **при продаже** экземпляра | долга нет |
| Себестоимость единицы | цена расчёта с владельцем | **не ведётся** |
| Непроданное | возвращаем владельцу | остаётся у нас |
| Где видно прибыль | выручка − расчёты с владельцем | отчёт по проекту (см. ниже) |

Третий вариант — обычная покупка с отсрочкой — структурно тот же приём, но долг
возникает сразу на всю поставку. Закладываем в тип поступления, в интерфейсе пока не показываем.

## Партии: почему без них не обойтись

При реализации долг именной: продали экземпляр — должны **его владельцу** по **его** цене.
Поэтому остаток товара хранится партиями (поставка → партия → остаток партии).

Списание — **FIFO**: продаётся самая старая партия, продавец ничего не выбирает.
В карточке товара видно, из каких партий состоит остаток.
Для своего выпуска партия тоже создаётся (чтобы считать штуки), но без цены расчёта.

## Деньги

Продаём гостям за наличные: **рупии, рубли, доллары**. Ценник один — в ₹.

```
чек          →  цена в ₹, валюта платежа, курс, сумма в валюте платежа
выручка      →  приход на подотчётный счёт «Магазин (₹ / ₽ / $)»
сдали ВГ     →  перевод «Магазин (X)» → «Касса (X)», той же валютой
```

Счёт «Магазин (₹)» уже существует — подотчёт департамента «Магазин», как у Кафе и Кухни.
Нужно добавить «Магазин (₽)» и «Магазин ($)».

Остаток подотчётного счёта = сколько наличных должно лежать в магазине. Сверка бесплатная:
пересчитал ящик, сравнил с остатком.

Рубли и доллары **не конвертируются** при продаже — лежат и сдаются в своей валюте,
поэтому курсовой разницы внутри ашрама не возникает. Курс нужен только чтобы
пересчитать рупиевый ценник в валюту платежа; применённый курс фиксируется в чеке.

В финмодуль выручка уходит **сводкой за смену** («Выручка магазина за 16 октября, 47 чеков»)
с переходом в список чеков. Каждый чек отдельной операцией не пишем — журнал утонет.

## Проект «Мурти Госвами»

Производство живёт не в магазине, а в финмодуле — на **объекте учёта**
(`fin_accounting_objects`). Сейчас объекты бывают только типа `retreat`;
добавляем тип `project` и объект «Мурти Госвами».

| Что | Как проводится |
|---|---|
| Резина, краски, формы | расход Мастерской, объект «Мурти Госвами» |
| Оплата мастерам | расход, тот же объект |
| Продажа мурти в магазине | выручка, тот же объект |
| Прибыль направления | отчёт по объекту (механизм уже есть) |

Затраты и выручка разъезжаются во времени: потратились на партию зимой, продаём год.
Поэтому прибыль проекта смотрим **накопительно за всё время**, а рядом показываем штуки:
выпущено / продано / осталось — видно, что часть денег ещё лежит на полке в виде мурти.

## Данные

```
shop_categories          книги, аудио, одежда, аюрведа, мурти, сувениры
shop_items               товар: названия ru/en/hi, транслит, фото, ед. изм.,
                         цена продажи (₹), источник (реализация | свой выпуск)
shop_batches             партия: ссылка на поставку, принято, остаток,
                         цена расчёта с владельцем (у своего выпуска — пусто)
shop_receipts            поступление: тип, владелец (fin_contractors), дата, автор
shop_receipt_items       строки поступления: товар, количество, цена расчёта, цена продажи
shop_sales               чек: дата, продавец, покупатель (необязательно),
                         валюта платежа, курс, итог в ₹ и в валюте, скидка с причиной
shop_sale_items          строки чека: товар, партия, количество, цена, скидка,
                         цена расчёта с владельцем на момент продажи
shop_returns             возврат покупателем (ссылка на чек)
shop_owner_returns       возврат непроданного владельцу
shop_writeoffs           списание: порча, утеря, дар, передано на служение — с причиной
shop_inventories/_items  инвентаризация: ведомость, факт, причина расхождения
shop_settlements         расчёт с владельцем: период, сумма, ссылка на расход в финмодуле
shop_shift_closures      закрытие смены: выручка по валютам, ссылка на операцию прихода
shop_rates               курс магазина ₽/$ → ₹ с датой (история)
shop_transactions        единый журнал движений товара
```

Все таблицы с `location_id` — на будущее, если точек станет больше одной.

## Экраны

1. **Касса** — главный. Поиск по названию и транслиту, плитка с фото и ценой, корзина,
   скидка на позицию или на чек с причиной, покупатель (гость из базы, необязательно),
   валюта платежа, расчёт сдачи. Кнопка «Продать».
2. **Смена** — что продано за день, выручка по валютам, кнопка «Закрыть смену»
   (приход в финмодуль) и «Сдать ВГ» (перевод в кассу).
3. **Приём товара** — владелец, строки, цена расчёта и цена продажи. Для мурти —
   «выпуск из Мастерской»: только количество.
4. **Владельцы товара** — у кого сколько принято, продано, возвращено, к оплате.
   Кнопка «Рассчитаться» делает расход в финмодуле.
5. **Товары** — цены, остатки, из каких партий состоит остаток, уценка.
6. **Инвентаризация** — ведомость → факт → расхождения с причинами → утверждение
   (по образцу кухни).
7. **Аналитика** — выручка и прибыль за период, отдельно перепродажа и свой выпуск,
   топ товаров, неликвид (лежит дольше N месяцев), стоимость остатка, средний чек.

## Права

| Код | Кто | Что может |
|---|---|---|
| `shop_sell` | продавец | касса, закрытие смены |
| `shop_receive` | заведующий | приём товара, цены, уценка |
| `shop_manage` | заведующий | инвентаризация, списания, возвраты |
| `shop_settle` | казначей | расчёты с владельцами, сдача денег |
| `shop_analytics` | руководство | аналитика и отчёты |

## Принятые допущения

Если какое-то неверно — лучше поправить до начала работы, потом дороже.

1. **Скидка за наш счёт.** Владельцу платим полную цену расчёта независимо от скидки покупателю.
2. **Долг владельцу — в рупиях**, даже если покупатель заплатил рублями.
3. **FIFO** списывает партии автоматически; физически мог уйти экземпляр другого владельца —
   для лавки это приемлемо и является стандартом консигнации.
4. **Курс магазина** задаётся вручную и живёт до следующего изменения; в чеке фиксируется применённый.
5. **Себестоимость своего выпуска не ведётся** — экономика только на уровне проекта.
6. **Возврат товара покупателем** — редкий случай, делается по номеру чека целыми позициями.

## Этапы

| Этап | Содержание | Результат |
|---|---|---|
| 1 | Товары, приём на реализацию, касса, смена, сдача денег | можно торговать |
| 2 | Владельцы: долги, расчёты, возврат непроданного | можно честно рассчитываться |
| 3 | Инвентаризация, списания, возврат покупателю | можно сверяться |
| 4 | Проект «Мурти Госвами», аналитика | видно прибыль |

## Открытые вопросы

- **Зарплата мастеров.** В `fin_payroll_accruals` нет привязки к объекту учёта. Если мурти
  делают люди на постоянной ставке, их зарплата в проект автоматически не попадёт.
  Пока — разовые выплаты обычным расходом на проект; для ставки нужна доработка payroll.
- **Общие материалы.** Если краски идут и на мурти, и на другие работы Мастерской,
  расход делится на две строки с разными объектами. Нужен ли удобный интерфейс для этого?
- **Кто продавцы** и будут ли смены с пересдачей ящика между людьми.
