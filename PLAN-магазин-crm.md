## Код Магазина — находки агента (статический разбор)

### Критично
1. Инвентаризация: экран считает разницу от текущего остатка, сервер `shop_apply_inventory` — от снимка `expected_qty` при создании ведомости → продажи между созданием и проведением списываются второй раз (shop-inventory.js:90,160,168,261).
2. Офлайн-очередь кассы: чек, отклонённый при досылке (например, смену закрыли), удаляется навсегда; в payload нет времени продажи и курса — `sold_at` и курс берутся на момент досылки (shop-till.js:127-142, 559).

### Серьёзно
3. Касса: параллельные разборы очереди (online + setInterval + старт) — ложный «отклонён: duplicate key», потеря новой офлайн-продажи при перезаписи массива (till:540-564).
4. Касса: товар исчез из каталога после перезагрузки → TypeError в рисоватьЧек, касса встаёт (till:200,230,245).
5. Касса: Math.ceil(итог/курс/шаг) — плавающая точка, $16 вместо $15 при курсе 90.6 (till:210).
6. Касса: parseFloat('12,5')=12; float-мусор в пожертвовании; дробные рупии (till:202,250,389,490,503,508).
7. Касса: цены и курсы грузятся один раз при открытии страницы; сервер берёт новую цену (till:74-101).
8. Касса на телефоне: шторка чека выше экрана без прокрутки (till.html:56-64).
9. Касса: перерисовка на resize сбивает фокус «Получено» (till:541).
10. Товары: пустая цена сохраняется как 0 (shop-items.js:100).
11. Даты по UTC в базе (`sold_at::date`, `current_date` в курсах) и по часам устройства на страницах (receive:252, analytics:133).
12. Приёмка: новый товар создаётся до проверки остальных строк → сироты и дубли (receive:149-177).
13. Приёмка: поиск названия без учёта вида приёмки → партия без владельца (receive:222).

### Средне
14. Смена: закрытие по устаревшему «ожидается» (shift:309-320).
15. Смена: пожертвования в валюте считаются как рупии (курс 1) (shift:98-124,232).
16. Смена: number-поле перерисовывается на каждый символ (shift:386-392).
17. Касса: скидка фиксируется суммой, не пересчитывается (till:498).
18. Касса: отказ сервера затирает уже набранный новый чек (till:420).
19. Касса: ошибки справочников (остатки, курсы, цели) проглатываются (till:75-86).
20. Возвраты: гонка при открытии чека (returns:43-70).
21. Возвраты: кнопка снова активна после успеха (returns:143-146).
22. Аналитика: гонка периодов; период(7) = 8 дней; пустая дата роняет RPC (analytics:134-153).
23. Инвентаризация: живая «Разница» только на русском (inventory:257).
24. Инвентаризация: «Провести» залипает выключенной; «Начать»/«Удалить» без блокировки (inventory:174-238).
25. Владельцы: «Мастерская» без проверки ошибок и предела 1000 (owners:61-75).
26. Владельцы: гонка «Вернуть непроданное» (owners:176-195).
27. Приёмка: история цен целиком без предела (receive:27).
28. Фото товаров без сжатия, старые не удаляются, ошибка update не проверяется (items:135-146).

### Мелочи
Отмена чека без блокировки; client_uid-запасной не UUID; дробное количество на кассе; Math.round долга владельцу; replace('%s') со спецсимволами; непереведённые строки и иконки категорий по русским названиям; ошибки на «Смене» игнорируются; касса открывает смену при каждом заходе (p_float 0); till.html utils.js?v=17.

### Скорость

## База Магазина — находки агента (проверено в откатах)

Все пять прав shop_* выданы одной роли shop_keeper (один пользователь — c9bb7961…, второй аккаунт Адриана).

### Критично
- К1. Возврат, затем отмена того же чека: товар возвращается на полку дважды; shop_shift_expected вычитает возврат по отменённому чеку, пакет — нет. Правка: отмена запрещена, если по чеку был возврат; for update в shop_return_sale; фильтр status='posted' в shop_shift_expected.
- К2. Отмена чека, ушедшего «в минус», после приёмки: товар владельца становится ничьим, долг теряется (shop_cancel_sale не обрабатывает shortfall-партию, в отличие от shop_return_sale).
- К3. Возвраты в пакете выручки: отрицательная сумма молча не проводится (accept_handover проводит только > 0); возврат своего товара вычитается из чужой части (мурти).
- К4. Разменный фонд меняется в любой момент смены (shop_set_float) без следа — так прячется недостача; размен при открытии не сверяется с прошлой сменой.

### Серьёзно
- С1. shop_owners открыта на прямой UPDATE с правом shop_receive: можно сменить contractor_id — долг уйдёт другому контрагенту финмодуля.
- С2. shop_upsert_owner переименовывает контрагентов финмодуля и цепляет любого по имени.
- С3. Гонки без блокировок: двойной возврат, двойная оплата владельцу, чек в закрытую смену, две shortfall-партии, два черновика инвентаризации.
- С4. Подарок/служебное списание чужого товара при политике «за счёт владельца» — владелец не получает ничего.
- С5. RLS: shop_can_view() на каждую строку (20 000 строк — 1,34 с вместо 1,8 мс).
- С6. Экраны обрезают данные на 1000 строках (owners, receive).

### Средне
Свой/чужой по текущему source, а не на момент продажи (и source меняется напрямую); дробное количество штучного товара; недостачу гасит любой владелец; инвентаризация ломается после продаж; одна «калитка» shop_can_view на все права — продавец видит себестоимость и долги; повтор чека при незакоммиченном первом даёт 23505; курс без срока годности и «сегодня» по UTC.

### Мелочи
Нет уникальных индексов на «одна открытая смена / один несданный пакет / один черновик / одна shortfall-партия»; cancel_sale без shop_sell; возврат не округляется до шага; purchase как реализация; мёртвые колонки; shop_round_step без search_path; индексы (дубли двух, не хватает 9).

### Данные сейчас
Целостность в порядке; одна партия с наследственным списанием без batch_id. Тестовый мусор на проде (смена с 16.10 открыта, несданный пакет, тестовый владелец, 10 товаров) — описан в docs/shop/test-results.md, чистить до заливки ассортимента.

### Серьёзно — открыто
- Права CRM в базе — это is_staff, а не права CRM: 20 из 41 сотрудника без view_crm/edit_crm (повара, фото, магазин, поклонение) видят 347 сделок, 1936 записей переписки, 200 платежей, могут удалить все задачи и переписку. - Публичная форма: слияние по имени-фамилии без контакта дописывает чужой карточке контакты атакующего; ответ «duplicate» — оракул «записан ли человек»; нет лимита (30 заявок подряд = 30 людей, сделок, задач); UTM до 500 КБ; email создаёт подтверждённую учётку на любой адрес.

### Средне
- Нет машины состояний: working → booked мимо invoiced, completed → lead, cancelled → completed.
- Автозадачи дублируются при повторном входе в стадию (1 → 5).
